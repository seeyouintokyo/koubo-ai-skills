# 素材和真实感

小红书要求真实内容不少于 AI 内容。AI 相关的选题更要靠实拍和手工截图撑住可信度。

所有包装都以真实可信、增加信息量为目的。一个画面如果既不真实、也没有给观众新信息，就换掉。

## 优先级

1. **录屏和手工截图**：用户自己录的操作过程、聊天记录、生成历史、画布。最真实，优先用。
2. **真实产物**：这条或上一条视频的成片画面、原片转写、粗剪记录、真实波形、真实运行日志、skill 文件、GitHub 仓库页，以及剪辑时自查用的分镜样帧拼图。
3. **代码画的解释图**：雷达图、打分表、门槛柱状图、流程链、时间轴、压低曲线。只在没有真实素材，或需要帮观众理解时用。
4. **AI 生成的画面**：最后才用，而且不能比真实素材多。

用真实数据重画的东西（比如按导出节点重画的生成画布），要告诉用户它不是截图。

## 每个知识点都要有画面

- 口播讲到一个点，画面就要同时出现对应的截图或解释图，跟着口播逐项出现。不要只有大字。
- 雷达图这类随口播实时变化的图最受认可，能用就用。

## 尺寸

- 截图和录屏要大：宽度至少占画面 90%（约 1000 像素），高度能给多少给多少。必要时把人缩成小头像，把画面让给素材。
- 多张截图拼贴只用在开头的快速展示；讲具体内容时一次只放一张，放大。
- 录屏可以裁掉无关区域、局部放大，或者用缓慢推镜跟着鼠标走。

## 品牌和隐私

- 侧栏、页头、模型选择器里的品牌名和 logo 要裁掉或模糊。滚动的录屏用 `scripts/ocr.swift` 逐帧找字再模糊。
- 用到的开源项目可以放 GitHub 页面截图，但不放大名字，不念出名字。
- 没真正用过的工具不要截图冒充；先问用户或真的跑一次再截。

## 动效

- 抖镜（节拍脉冲、切镜冲击、手持抖动）只加在素材层，人物和房间只保留缓慢推进。`template/engine-v4.js` 已经这样实现。
- 每一步结尾的截图清单卡不超过 1.5 秒，而且每次都要有变化：入场方式不同，逐条打勾，进度前进，最后盖“收藏”章。静止的停顿会显得冷清。
